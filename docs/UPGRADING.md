# 升级到 6.2.0

6.2.0 增加管理员网页端口管理，与桌面/CLI 客户端 6.1.1 兼容，无需为此功能重装客户端。

1. 备份 SQLite、`.env`、密钥和现有 Compose 文件，按下方更新步骤使用新 Release 包。保留原项目名、数据卷和现有端口覆盖文件。
2. 已准备 TCP/UDP 端口池的部署直接打开「系统设置 → 端口与协议」。首次保存前沿用原启用状态和范围，既有连接与公网端口不变。
3. 原来仅部署 Web 的主机需要一次性添加 `deploy/compose.ports.yaml` 并放行所需端口。详见[端口管理与首次准备](SELF_HOSTING.md#在管理员界面管理-tcpudp)。此后在网页里管理，不需要反复编辑 `.env`。
4. 网页设置保存在数据库，常规重启和升级会保留。缩小底层部署端口池前，先在后台调整或暂停受影响连接并保存范围。如果保存的范围已超出新的部署池，协议会显示不可用，需要在后台纠正。

回退到 6.1.x 时，旧程序只读取部署环境，忽略网页保存的协议策略。回退前应把要保留的启用状态与范围同步到旧部署配置，并使用备份；只准备端口池的 `compose.ports.yaml` 不能让 6.1.x 支持网页管理。

## 从旧版本升级到 6.0 及以上

6.0 重做各端界面，并加强用户与设备边界。建议在维护窗口升级服务端、桌面客户端和 Android。

## 升级前

备份 SQLite 数据库、`.env`、`deploy/secrets/` 以及当前版本的 Compose 文件。保留现有域名与密钥；不要重新生成部署凭据覆盖旧文件。确认可以用最早创建的有效管理员账号登录。

## 数据迁移

服务端启动时自动执行编号迁移。原有普通用户、设备、连接、域名和流量保留。

- 多管理员部署保留最早创建的有效管理员；同一创建时间按账号 ID 排序。其余管理员转为普通用户，旧会话失效，重新登录后仍可使用自己名下的资源。迁移记录写入审计。
- 数据库约束保证部署只有一名管理员。管理员不能删除或禁用自己。
- 删除普通用户会关闭账号、撤销会话与设备凭据，并移除账号连接。历史审计和流量保留；原用户名可用于创建全新的账号，新账号不会继承旧资源。
- 桌面和 CLI 的设备会话仅访问本机资源。浏览器及手机管理会话可管理账号名下的多台设备。

## 更新

将部署包解压至新的版本目录，复制既有 `.env` 和 `deploy/secrets/`，继续使用原 Compose 项目名与数据卷。`compose.release.yaml` 固定了当前版本的镜像摘要。

```sh
docker compose -f compose.yaml -f compose.release.yaml config --quiet
docker compose -f compose.yaml -f compose.release.yaml pull
docker compose -f compose.yaml -f compose.release.yaml up -d
docker compose ps
```

如果使用 TCP / UDP 覆盖文件，请在每条命令中保留原先的覆盖文件与端口设置。随后升级设备安装包与 Android APK，并检查登录、设备状态、已有地址访问、暂停与恢复。

## 回退

保留旧部署目录与升级前备份。若需要回退，先停止 6.0 服务，再用旧镜像和升级前数据库恢复。升级后的账号删除、角色调整与会话撤销不能仅通过回退镜像恢复。
