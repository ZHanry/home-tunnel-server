# 安全模型与测试边界

项目处于正式发布。下列描述对应当前组件职责，不能替代真实环境验证或稳定性承诺。

## 信任边界

- **公网入口**：Caddy 处理公开 HTTP / HTTPS；控制中心、网关与 SQLite 不作为独立公网服务暴露。
- **身份与资源**：服务端验证会话、角色与资源归属，普通用户的设备和连接按账号隔离。
- **设备授权**：客户端同步配置和短期租约；FRPS 向控制中心核对登录、代理创建及心跳授权。
- **服务间通信**：使用生成的内部密钥，部署配置将内部通信与公网入口区分开。
- **本地客户端状态**：共用 Go 客户端把设备状态和凭据写入配置的本地 JSON 文件，设置文件及目录权限。桌面模式使用用户数据目录，headless 使用服务账号目录；不应将此文件上传到反馈中，也不能把它描述为 Windows Credential Manager 存储。
- **Android**：手机作为远程管理端；应用关闭系统备份，使用自己的会话与本地状态实现，不在手机上运行 FRP Agent。

## 受管 Agent

Agent 采用固定版本的 FRP 源码，仅接受服务端允许的配置。
它核对服务器地址、传输类型、域名与明确授权的公网端口，拒绝通用 FRP 命令、visitor 和任意插件配置。
完整安装包还绑定对应 Agent 的哈希。能修改整个客户端安装环境的本地用户仍处于本地信任边界内。

配置生成器提供 FRPS 证书，客户端通过所选择的 HTTPS 服务端获得信任材料。
测试时应使用完整生成的证书配置，检查主机名、证书信任和 Agent 校验失败时的行为。

## HTTP 与原始端口流量

HTTP / HTTPS 经过 Caddy 和网关，可以应用 Web 访问控制、速率限制与流量配额。
TCP / UDP 直接经过 FRPS，不能使用这些 HTTP 层策略；应用本身负责认证和加密。
原始端口由部署范围与管理员授权共同限制，UDP 还需要考虑服务的反射放大行为。
撤销与网络故障测试应观察实际心跳与租约窗口，不能把策略通知理解为所有传输上的瞬时断流。

## 产物与更新

安装包由各组件仓库发布，保留哈希、构建来源和签名校验。
GUI 的更新检查与用户填写的服务端地址分开，下载内容经过 SHA-256 校验；这不等于已经具备完整的稳定分发和平台签名信任体系。
Android 签名安装包通过受限环境构建，验证应用标识、证书和产物。

## 不在保护范围内

- 被公开的本地应用自身存在的漏洞或弱认证。
- 已被控制的服务器、Docker 守护进程、管理员账号或本地用户环境。
- 公网接入带宽在请求抵达应用策略前被耗尽。
- 未经验证的第三方安装包、任意 FRP 配置或泄露的设备状态。

发现疑似漏洞使用 [SECURITY.md](../SECURITY.md) 的私密报告入口。
